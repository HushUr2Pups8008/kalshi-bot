# Plan: v0.24.0 -- Live Safety & Automated Tests

## Context

v0.23.0 fixed the bankroll desync bug and added defensive market copies / Kelly shadow
sizing. This plan covers the remaining three items from the "Top 7 Improvements" code
review: the live loss limit circuit breaker (#2), order retry with exponential backoff

## What This Implements

### 1. Live Loss Limit Circuit Breaker (#2 from plan -- CRITICAL)

**Problem:** In live mode, a bad LLM day or broken signal could place dozens of losing
trades with real money before any human notices. No drawdown circuit breaker existed.

**Solution:**
- `config.py`: Added `live_loss_limit_pct` field, reads `LIVE_LOSS_LIMIT_PERCENT` env var
  (default `0.10` = 10% of bankroll).
- `.env.example`: Documented with explanatory comment.
- `executor.py`:
  - `_session_start_balance: Optional[float]` -- seeded on first `get_balance()` call.
  - `_live_halted: bool` -- once set, ALL subsequent `_validate()` calls short-circuit.
  - `_check_live_loss_limit(balance) -> bool` -- seeds baseline on first call; returns
    True if `(start - current) >= start * limit_pct`.
  - `set_shutdown_callback(cb)` -- lets `main.py` wire an async shutdown coroutine.
  - `_validate()` updated: checks `_live_halted` first (O(1) short-circuit), then calls
    `get_balance()` and `_check_live_loss_limit()`.
- `main.py`: Wires the shutdown callback after executor construction:
  ```python
  self.executor.set_shutdown_callback(
      lambda: asyncio.create_task(_shutdown(self))
  )
  ```

**Non-obvious design decisions:**
- Session balance seeded on FIRST `get_balance()` call, not at bot startup. This means
  the limit is relative to the balance at the time of the first live order attempt, not
  the balance when the bot was launched. This is intentional -- the bot may run for hours
  in paper mode or idle before any live order is attempted.
- `_live_halted` is sticky -- once set, it never clears within a session. Even if balance
  "recovers" (paper positions resolve profitably), the halt persists. This prevents the
  bot from resuming live trading after a loss limit breach without explicit human restart.
- `get_balance()` is NOT called after halt is set (early return). This avoids unnecessary
  API calls and prevents any edge case where a failing balance API hides the halted state.

### 2. Order Retry with Exponential Backoff (#4 from plan -- HIGH)

**Problem:** A single network timeout or 5xx from Kalshi permanently skipped the trade
opportunity. At 1-3 live trades/day, missing even one is significant.

**Solution (executor.py `_execute_live()`):**
- 3-attempt loop with `asyncio.sleep(1)` after attempt 1, `asyncio.sleep(2)` after attempt 2.
- `_is_retryable_error(error: str) -> bool` static method:
  - Retry: "timeout", "503", "429", "502", "504", "500", "connection", "network", "reset"
  - No retry: "400", "403", empty string, None
- On permanent error: log and return `None` after one attempt.
- On transient error after 3 attempts: log critical and return `None`.

**Non-obvious design decisions:**
- `_is_retryable_error` is a static method on the class (not a module-level function) so
  it can be tested directly via `TradeExecutor._is_retryable_error(...)` without
  constructing an executor.
- Uses `asyncio.sleep` (non-blocking) not `time.sleep` -- the retry loop is in an async
  method, so blocking sleep would hold the event loop.
- No retry on 400 Bad Request -- this indicates a malformed order that will never succeed.
  No retry on 403 -- this indicates an auth failure that requires human intervention.

### 3. Automated Test Suite (#3 from plan -- HIGH)

**Stack:** pytest + pytest-asyncio, `asyncio_mode = auto`, `:tmp_path` SQLite for
paper_trader tests (not `:memory:` -- PaperTrader constructor writes DDL to the file).

**74 tests, 0 failures. Modules:**

| Module | Tests | What it catches |
|--------|-------|-----------------|
| `test_kelly.py` | 31 | Sizing regressions, min-edge gate, time discount, cap |
| `test_paper_trader.py` | 10 | Bankroll atomicity, P&L accounting, keyword_outcomes |
| `test_signal_analyzer.py` | 16 | JSON extraction, LLM response parsing, keyword scoring |
| `test_market_matcher.py` | 11 | Tokenization, Jaccard + geo-boost |
| `test_executor.py` | 13 | Loss limit, retry logic |

**Non-obvious design decisions:**
- `_extract_json` keeps the LAST valid JSON object found (scans all `{` positions left to
  right, keeps last successful parse). Tests verify this behavior explicitly, not the
  intuitive "outermost" assumption.
- `_similarity` is NOT pure Jaccard -- it adds `0.03` per intersection token found in
  `_GEOPOLITICAL_BOOST`. Test assertions use `> 0.5` not `== 0.5` to accommodate this.
- YES-direction keywords in `GEOPOLITICAL_SIGNALS` are multi-word phrases ("missile strike",
  "shelling") not single words ("attack"). Tests use actual phrase matches.
- `SourceCredibility` and `dataclasses.asdict` are patched in paper_trader tests to avoid
  needing a fully populated DB state for tests that don't exercise those paths.
