### 1. [LIVE RISK - CRITICAL] Bankroll Desync Bug in resolve_market()

**File:** `trading/paper_trader.py` -- `resolve_market()`, around line 370-420

**Problem:**
`_credit_bankroll(total_payout)` is called OUTSIDE the `with self._conn:` atomic block.
If the process crashes between the DB commit and the bankroll credit, the trade is
marked resolved in the DB but bankroll is permanently understated. Compound over time
-> bot bets smaller and smaller fractions of its actual equity.

```python
# CURRENT (broken):
with self._conn:
    self._conn.execute("UPDATE paper_trades SET ...")  # resolves the trade
# <--- crash here = bankroll lost forever
self._credit_bankroll(total_payout)

# FIX: Move _credit_bankroll inside the with block:
with self._conn:
    self._conn.execute("UPDATE paper_trades SET ...")
    self._credit_bankroll(total_payout)   # atomic with the resolution
```

**Verification:** Add a test that kills the process between resolve and credit; confirm
bankroll matches sum of resolved trade payouts after recovery.

**Effort:** 3-line move. Implement first.

### 2. [LIVE RISK - CRITICAL] No Live Loss Limit Circuit Breaker

**File:** `trading/executor.py` -- `_validate()`, `config.py`

**Problem:**
In paper mode, flat contracts cap downside. In live mode, there is no drawdown
circuit breaker. A bad LLM day or a broken signal could place dozens of losing
trades with real money before any human notices.

**Fix:**
1. Add `LIVE_LOSS_LIMIT_PERCENT` to `.env.example` and `config.py` (default: 10%)
2. In `executor._validate()`, before executing a live order, check:
   ```python
   if cfg.live_mode:
       session_pnl = self._portfolio.session_pnl()  # sum of resolved live trades today
       if session_pnl < -(cfg.bankroll * cfg.live_loss_limit_pct):
           log.critical("LIVE LOSS LIMIT HIT -- halting all trading")
           raise LiveLossLimitError()
   ```
3. `LiveLossLimitError` propagates to `main.py` and triggers clean shutdown

**Verification:** Paper-mode unit test simulating 10% drawdown; confirm no further
orders are placed after limit hit.

**Effort:** ~2-3h. Implement before any real money is deployed.

### 4. [HIGH] Order Placement Not Retried on Transient Failures

**File:** `trading/executor.py` -- `_execute_live()` or equivalent

**Problem:**
A single network timeout or 5xx from Kalshi permanently skips the trade opportunity.
At live trade frequency (~1-3/day), missing even one trade is meaningful. There is no
retry with exponential backoff.

**Fix:**
```python
import asyncio

async def _place_order_with_retry(self, ...):
    for attempt in range(3):
        try:
            return await self._rest_client.place_order(...)
        except (aiohttp.ClientError, KalshiApiError) as exc:
            if attempt == 2 or not _is_retryable(exc):
                raise
            await asyncio.sleep(2 ** attempt)   # 1s, 2s backoff
```

`_is_retryable`: retry on 429, 500, 502, 503, 504, connection errors.
Do NOT retry on 400 (bad request) or 403 (auth failure).

**Verification:** Mock the REST client to fail twice then succeed; confirm order placed.

**Effort:** ~1-2h.

### 5. [MEDIUM] Shared Market Object Mutated Without Defensive Copy

**File:** `main.py` -- `_process_candidate()`, around the WebSocket price-update path

**Problem:**
The `KalshiMarket` object is pulled directly from the shared market cache and its
`yes_price`/`no_price` fields are updated in-place from WebSocket events. A concurrent
task reading the same object sees a partially-updated price mid-update. This is a latent
race condition -- not crashing now because the GIL masks it, but it WILL cause
incorrect probability estimates under load.

**Fix:**
```python
import dataclasses
market = dataclasses.replace(market)   # defensive copy before any mutation
market.yes_price = updated_price
```

Add this one line before any mutation of a market object retrieved from the cache.

**Verification:** Confirm the cache object is unchanged after processing.

**Effort:** 30-minute fix.

### 6. [MEDIUM] Reddit Public JSON Fragility (2600+ 403s/week)

**File:** `feeds/reddit_monitor.py`

**Problem:**
The bot uses Reddit's public JSON endpoint (`reddit.com/r/X.json`). Reddit throttles
and blocks unauthenticated requests aggressively. Analysis log shows 2600+ 403s/week.
Each 403 is a missed signal window. During a fast-breaking story, the 60s poll window
combined with 403 backoff means the bot may miss the first 5-10 minutes entirely.

**Fix:**
1. `.env.example` already has `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`.
2. Enforce OAuth token flow in `reddit_monitor.py`:
   ```python
   # POST to https://www.reddit.com/api/v1/access_token
   # Use client_credentials grant
   # Attach Bearer token to all subsequent requests
   # Refresh token 60s before expiry (tokens last 1h)
   ```
3. Use `oauth.reddit.com` base URL (required after auth).

**Note:** REDDIT_CORE_SUBREDDITS are always polled regardless of quality gates -- do
not break this invariant.

**Effort:** ~2-3h. The infrastructure (env vars, aiohttp session) is already in place.

### 7. [MEDIUM] Paper-to-Live Sizing Discontinuity

**File:** `trading/paper_trader.py` -- `record_trade()`, `config.py`

**Problem:**
Paper mode uses flat 5 contracts (`PAPER_FLAT_CONTRACTS`). Live mode uses Kelly
sizing. This means paper performance metrics (win rate, P&L distribution) are measured
on a flat-bet system that doesn't reflect what Kelly would actually do in live.
A trade that Kelly would size at 1 contract (low confidence) looks identical in paper
to a trade Kelly would size at 8 contracts (high confidence). The P&L trajectory is
misleading.

**Fix (two options):**
- **Option A (recommended):** Add a `PAPER_USE_KELLY` env var (default: false for
  backward compat). When true, paper trades use Kelly sizing but capped at
  `PAPER_FLAT_CONTRACTS` as a hard max. This lets you evaluate Kelly behavior before
  live.
- **Option B:** Log the Kelly-recommended size alongside the flat size in paper_trades
  so analytics can retroactively show what Kelly would have done.

Option B has zero behavioral risk and is ~30 min of work. Option A requires verifying
bankroll accounting is consistent with Kelly-sized paper trades.

**Effort:** Option B: 30 min. Option A: 1-2h + verification.
