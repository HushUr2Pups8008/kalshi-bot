# v0.27.3 Plan: Ollama Error Audit Script (Read-Only Diagnostic)

## Context

After the v0.27.1/v0.27.2 LLM fixes (remove repetition_penalty, correct OLLAMA_MODEL),
the system started producing successful inference calls. The audit task required a dedicated
diagnostic script to convert the vague suspicion ("maybe Ollama was busy") into concrete,
evidence-backed classification of every Ollama HTTP error in the historical logs.

---

## What the Script Does

`scripts/ollama_error_audit.py` is a pure read-only script. It:

1. Reads `logs/app/bot.log` (and optionally rotated archives with `--rotated`)
2. Finds all lines containing Ollama HTTP error events (both old DEBUG format and new WARNING format)
3. Also captures timeout/connection lines that don't have HTTP status codes
4. Classifies each event into one of five buckets:
   - `model_not_found` -- HTTP 404 + body contains "not found"
   - `timeout_or_connection` -- timeout wording or circuit open / connection errors
   - `server_error` -- HTTP 5xx
   - `bad_request` -- HTTP 400
   - `other` -- anything else (403, 404 without "not found" body, etc.)
5. Outputs: summary by bucket + status code, per-bucket examples (top 5), most recent 10
   errors, time-gap / burst analysis, and a plain-English interpretation

---

## Architecture

### parse_log_line(line) -> OllamaErrorEvent | None
Pure function. Tries two patterns:
- `_OLLAMA_HTTP_RE`: matches "Ollama HTTP NNN" or "Ollama returned HTTP NNN" (old format)
- Keyword fallback: lines containing ("timed out", "timeout", "circuit open") with "ollama"

### classify(status, body, line) -> str
Pure function. Applies bucket rules in priority order:
1. Timeout keyword check first (can co-exist with a status code)
2. Status-code rules (404+not_found, 5xx, 400)
3. Fallback: OTHER

### gap_analysis(events) -> dict
Computes time gaps between consecutive events and groups them into bursts
(consecutive errors within 5 seconds = same burst). Useful for distinguishing
"burst of retries on one signal" from "steady drip across the day".

---

## Non-Obvious Design Decisions

- **Old format (no body) classified as OTHER, not model_not_found**: The pre-v0.27.1
  format `"Ollama returned HTTP 404"` has no body snippet (just the status code).
  Without "not found" in the body we cannot confirm it's a model-not-found 404 vs
  some other 404, so it goes to OTHER rather than making a false classification.

- **Timeout check before status-code checks**: A response could theoretically carry
  both a status code and timeout-related body text. Timeout is checked first so a
  misrouted timeout doesn't end up in model_not_found.

- **`--rotated` gives chronological order**: rotated files are sorted alphabetically
  (bot.log.1, bot.log.2026-03-23, ...) and prepended before the current log so the
  report's "most recent 10" section is accurate.

- **`raw` truncated to 300 chars**: prevents giant log lines from bloating memory
  or report output while still capturing enough context.
