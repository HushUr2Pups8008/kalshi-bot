## NOTES ON TRACKING SYSTEMS

1. **Single source of truth:** profit_path_debt_log.md is explicitly the unified technical debt tracker (supersedes former macos_migration_debt.md; broader scope). All other tracking files are supporting evidence artifacts or cycle-specific diagnostics.

2. **Cycle-driven:** Many governance files (audits, reports, status checks) are keyed to specific development cycles (Cycles 12–17C in evidence). Older cycles (e.g., 2–11) are likely archived. This creates a time-series of cycle artifacts rather than a permanent index.

3. **Soak-phase artifacts:** Phase 2 governance shadow-soak (PROFIT-PHASE2-001) is generating daily/per-event monitoring files. These are temporary (PROFIT-PHASE2-001 target close 2026-05-15) and should be consolidated into a single soak-run ledger entry post-completion.

4. **Wave-deploy artifacts:** Pre-Wave-1-deploy audits (risk, readiness, dry-run, hygiene) were generated in a burst (2026-05-05 cluster). Most are one-shot pre-gate artifacts. Post-Wave-1, these should be archived and a "post-Wave-1 readiness audit" should launch for Wave-2 conditions.

5. **Debt item ↔ governance file relationship:** Many governance audits (e.g., 2026-05-05-doc-cross-link-integrity-audit.md) discover issues that spawn profit_path_debt_log.md entries (e.g., PROFIT-DOC-002). This is intentional (governance artifacts are discovery; debt log is action tracking). However, the lack of a formal "audit → debt item" index makes it hard to know which debt items originated from which audit without reading both files.
